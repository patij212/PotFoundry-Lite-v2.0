## Verdict up front

**Escalation MECHANISM design: SOUND** (minimal, additive, default-off byte-identical seam
identified in the real kernel, reuses existing 2:1-balance for T-junctions for free).
**Closed-form flagging CRITERION as literally specified in the task brief: REFUTED** — the naive
per-facet `predictedSag = kappaSup(4-point) · longestEdge² / 8 > 0.01` test measured on the exact

## 1. The escalation mechanism (kernel primitive) — DESIGNED, NOT YET APPLIED

### 1.1 Where featureLevel lives today

`ConformingWall.ts` (`buildConformingWall`, ~line 805-828) computes ONE scalar `featureLevel` for
the whole wall and builds:
```ts
type FeatureRefineSpec = { level: number; intersects: (u0,t0,size)=>boolean };
featureRefine = { level: featureLevel, intersects: buildFeatureIntersector(refineLines) };
```
This is handed to `new PeriodicBalancedQuadtree(field, sampler, { ..., featureRefine, ... })`.
Inside the quadtree, `refine()` (fresh build) and `shouldSplitHierarchyNode()` (budget-search
capture/materialize path — used when `targetTriangles` triggers the scale search, which
production Gyroid does) BOTH independently compute, per visited cell:
```ts
const belowFeatureFloor =
  featureRefine !== undefined &&
  c.level < Math.min(featureRefine.level, cap) &&
  intersects(c.iu*uSize, c.it*tSize, Math.max(uSize,tSize));
```
i.e. `featureRefine.level` is already a uniform FLOOR applied to every feature-crossed cell — this
is exactly the mechanism the (REFUTED) "global featureLevel 11→12" experiment bumped, uniformly,
for every one of the (many thousands of) cells the Gyroid val=0 curve threads through the WHOLE
wall — not just the ~166 hot knee arcs.

### 1.2 The minimal seam: `levelAt` on `FeatureRefineSpec`

Add ONE optional field, additive only:
```ts
type FeatureRefineSpec = {
  level: number;
  intersects: (u0: number, t0: number, size: number) => boolean;
  /** OPTIONAL per-cell target level (>= level), evaluated ONLY on cells that already pass
   *  `intersects` (cost-gated). Returns the ESCALATED floor for THIS cell; absent/lower than
   *  `level` ⇒ no change. Default-absent ⇒ byte-identical to today. */
  levelAt?: (u0: number, t0: number, size: number) => number;
};
```
and change the per-cell test (in BOTH `refine()` and `shouldSplitHierarchyNode()` — factor into
one shared private `PeriodicBalancedQuadtree` method so the two call sites cannot drift) to:
```ts
// gate on intersects FIRST (cheap, bucketed) before ever calling levelAt (curvature eval).
const onFeature = featureRefine !== undefined && c.level < cap && intersects(...);
const targetLevel = onFeature && featureRefine.levelAt
  ? Math.max(featureRefine.level, featureRefine.levelAt(u0, t0, size))
  : featureRefine?.level;
const belowFeatureFloor = onFeature && targetLevel !== undefined && c.level < Math.min(targetLevel, cap);
```
`levelAt` absent ⇒ `targetLevel === featureRefine.level` ⇒ **byte-identical to current production
behavior** (proof obligation for the next arm: an explicit byte-identical-off unit test, following
this codebase's own convention for every other opt-in flag in this file).

**Why this is genuinely cell-scoped and not a re-run of the REFUTED global bump:** `levelAt` is
called ONLY on cells that already pass the cheap `intersects` bucket test (a small subset of the
whole domain) AND only escalates a cell ABOVE the existing `featureRevel.level` floor when its OWN
`levelAt(u0,t0,size)` says so — cells whose criterion doesn't fire keep the SAME `featureRefine.level`
floor as today. This is the literal cell-scoped mechanism the charter asked for: only cells
individually flagged move past the baseline.

**Why this avoids the JACOBIAN-SIZING-MARGIN quantization trap:** the existing (different, already
-shipped-flag-gated) `AnalyticCurvatureFloor.ts` → `MetricSizingField.curvatureFloor` route feeds a
CONTINUOUS κ(u,t) into a `resU×resT` grid that is then **Lipschitz-graded** (`gradeRatio`) — a
localized κ spike gets smeared into its neighbourhood by the grading pass, and the *continuous*
target `h=sqrt(8·maxSag/κ)` is then quantized down into a discrete quadtree level anyway. The
recent Jacobian-sizing-margin arm found that lever "level-quantized DEAD" at its residual loci —
consistent with continuous-target-then-quantize being lossy. `levelAt` sidesteps this entirely: it
requests a **discrete level integer directly**, with NO grading pass and NO separate continuous
sizing-field round-trip — it is a pure, local, per-cell decision at the exact point the quadtree
already makes its own discrete decisions.

### 1.3 T-junction propagation — free, no new code

`PeriodicBalancedQuadtree`'s constructor calls `this.refine(...)` (which is where `levelAt` would
fire) and THEN `this.balance(opts.maxLevel)` (2:1 balance) unconditionally, regardless of WHY a
leaf split (sizing field, `minUniformLevel`, `featureRefine.level`, or the new `levelAt` floor).
`balance()` is refinement-source-agnostic — it only looks at the resulting leaf set and enforces
2:1 by splitting coarse neighbours of any leaf that ended up too fine. **No new T-junction code is
needed**; P2.0's ~89k-edge T-junction estimate was a *cost* characterization (facet count growth
from balance-propagated splits), not a missing mechanism — the existing `balance()` already is that
mechanism, exercised identically to how `minUniformLevel`/`featureRefine.level` already drive it in
production today.

### 1.4 Default-off wiring (ConformingWallOptions → WatertightAssembly → the twin)

Add `curvatureCellEscalation?: (u0,t0,size)=>number` (or similar) to `ConformingWallOptions`, piped
through unchanged to `featureRefine.levelAt` only when `featureLines`/`refineLines` is non-empty (mirrors
how `featureLevel` itself is already gated). Absent (default) ⇒ `featureRefine.levelAt` is
`undefined` ⇒ §1.2's byte-identical branch. `AssemblyWallOptions`/`assembleWatertight` would forward
it exactly like `outerCurvatureFloor`/`outerMaxKappa` are forwarded today (outer wall only — features
are outer-only, per the existing comment at `WatertightAssembly.ts`).

## 2. The flagging criterion — MINIMAL PROOF result: REFUTED as specified

### 2.1 What was tested

`research/bridge/_tierc_p2_1.test.ts` (`PF_TIERC_P2_1=1`), reusing the EXACT P2.0 champion twin
(hash `51a25eba-6a58e3e1` reproduced, non-vacuity confirmed) and `gyroidAnalyticCurvature` /
`GPC_FIELD` / `gpcR0` from `_gyroid_prodclose_lib.ts` (the closed-form the task brief named):

```
predictedSag(f) = kappaSup(f) * longestEdge3D(f)^2 / 8
kappaSup(f) = max( kappa(centroid), kappa(v0), kappa(v1), kappa(v2) )   // 4-point cell-sup proxy
flag L1 if predictedSag > 0.01 ; flag L2 (of the L1 set) if predictedSag > 4*0.01
```
scored on **every one of the 2,242,984 outer facets** (exact, not sampled) against the
Newton-CONFIRMED hot set (`armA3_char_confirmed.json`, 1,890 unique facets) and, for the L2 tier,
against P2.0's OWN banked per-facet Newton ground truth (`p2_0_s2_partial.json`, 1,710 rows with
real `usedLevel2` labels — zero new Newton calls needed for that check).

### 2.3 Mechanism diagnosis (why it fails both ways at once)

The false positives (sampled: `p2_1_summary.json.falsePositiveSample`) have **kappaSup ≈ 6.9–12.7
mm⁻¹** and **h ≈ 0.08–0.19 mm** — ordinary Gyroid TPMS curvature (the surface is intrinsically
saddle-curved almost everywhere along the band, not just at the knee) combined with base-mesh cell
sizes that were never specifically sized against *this* exact 0.01mm target. An **absolute**
threshold trips on that combination almost everywhere the base mesh happens to be locally coarse,
totally independent of the genuinely-anomalous knee.

Simultaneously, the missed hot facets (269/1,890, recall shortfall) are consistent with **under-
sampling the true curvature spike**: this codebase's OWN `buildGyroidCurvatureFloor` docstring
(`_gyroid_prodclose_lib.ts` lines ~486-493) explicitly measured that a coarse cell-sup (SUB=6, 13×13
sub-samples) under-reads this exact field's peak κ by **99.8%** (2.27 vs the converged 1359.0 mm⁻¹)
and required **SUB=24 (49×49 = 2,401 dense sub-samples)** to converge to within 0.02%. This arm's
criterion used only **4 points** (centroid + 3 vertices) — far coarser than even the already-too-coarse
SUB=6 case. The measured kappaSup values (≈7–13, everywhere including the false positives) never
approach the documented ≈1350 mm⁻¹ peak, circumstantially confirming the spike is being straddled
and missed by the sparse sampling (not independently re-verified with a dense sweep in this arm due
to time budget — **flagged as the first thing to confirm before reusing this diagnosis**).

**Two independent, compounding failures, not one:**
1. **Absolute vs. delta.** The existing (separate, already-shipped) `MetricSizingField.curvatureFloor`
   mechanism is careful to take `kappa = max(kappa_SAMPLER, kappa_floor)` — i.e. it only matters
   where the analytic floor EXCEEDS what the mesh's own existing curvature estimate already
   accounted for. This arm's criterion instead tested an ABSOLUTE `predictedSag > tol`, with no
   reference to what the base mesh's own sizing already assumed — so it re-flags huge swathes of
   already-adequately-sized cells whose ordinary (non-knee) curvature was already priced in.
2. **Sparse cell-sup.** 4-point sampling cannot resolve a spike documented (in this exact codebase,
   for this exact field) to require ~2,401 sub-samples to converge — so the genuinely hot cells are
   scored using an under-read κ, weakening their signal relative to the (already-too-loud) ordinary-
   curvature false-positive noise floor.

### 2.4 The fix for the next arm (not attempted here — time-boxed proof arm)

- **Make it a DELTA test, not absolute:** flag a feature cell only when `kappaSup_dense(u,t)` at that
  cell **exceeds what a plain (non-escalated) build would already have sized it to** — i.e. compare
  against the ALREADY-BUILT cell's actual existing predicted sag under the field that sized THIS
  mesh (reuse `field.edgeLength(u,t)` / the sampler-driven `principalCurvatureMax`, matching the
  `max(kappa_sampler, kappa_floor)` pattern the existing curvatureFloor mechanism already uses,
  reused for consistency rather than reinvented).
- **Reuse `buildGyroidCurvatureFloor`'s ALREADY-CALIBRATED SUB=24 dense cell-sup verbatim** instead
  of a 4-point proxy — it is sitting right next to `gyroidAnalyticCurvature` in the same file,
  purpose-built and empirically validated for this exact under-sampling failure mode.
- Re-run this arm's EXACT precision/recall/closure harness (`_tierc_p2_1.test.ts`, already built and
  reusable) against the corrected criterion before touching the kernel — the escalation MECHANISM
  design in §1 needs no changes; only the flagging math needs replacing.

## 3. Closure inheritance — NOT reached (gated on §2's criterion passing first)

The charter's GATE required "the curvature-flagged escalation closes the knee residual to ≤0.01
… AND the flagging criterion's precision/recall … is good." Since precision/recall failed hard,
the closure leg was not separately re-run — it does not need to be: P2.0 already proved closure
for the CORRECT (Newton-known) hot set at bounded cost; this arm's job was only to test whether a
closed-form criterion could stand in for that oracle, and it currently cannot (its own flagged set,
at 380k facets / +202% tris, is not the P2.0 population and would not be expected to reproduce
P2.0's bounded-cost closure — confirming that number was not useful information given how far off
recall/precision already are).
